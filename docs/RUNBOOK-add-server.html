Adding a New WireGuard Server

22 numbered steps, droplet → live. Each step is tagged with where to run it. Worked from the real bring-up of de-fra-01 (Frankfurt) — every command was actually run.

💻 Your Mac 🖥️ The droplet 🗄️ SQL migration ☁️ Render dashboard
⚡ Automated path (recommended)

The scripts in scripts/ run this whole runbook for you — every step below is verified and logged. Create the droplet in the DigitalOcean dashboard, copy its IP, then from the repo root on your Mac:

./scripts/provision-node.sh            # Half A — prompts for IP, id, subnet, secret
./scripts/activate-node.sh <server-id> # Half B — writes migration + registry, commits
git push                               # you deploy
./scripts/verify-node.sh <server-id>   # confirms the node is live end-to-end

The manual steps below are the reference the scripts are built from — use them to understand a step or debug a failure.

Golden rule — which machine?

Any command that starts with ssh or scp … root@<NODE_IP> runs on your Mac (it reaches into the droplet). Everything else marked 🖥️ droplet runs inside your SSH session. Running a Mac step on the droplet is the #1 mistake.

§0 · The mental model #

Three planes; adding a server touches two of them:

📱 iPhone ──HTTPS──▶ ☁️ Control plane (this repo, on Render) ──HTTPS/TLS──▶ 🖥️ Droplet (the node) nyx-edge.onrender.com agent :8443 + wg0 :51820 │ ▲ └──────────────── encrypted WireGuard tunnel (UDP 51820) ─────────────────────┘ THE ACTUAL VPN — never touches Render
  • Control plane (Render) — owns the Postgres servers catalog, allocates tunnel IPs, drives each agent over TLS. Never carries VPN traffic.
  • The node (DigitalOcean droplet) — runs WireGuard (wg0) + the node-agent on :8443. This is the real VPN.
  • The phone — builds the encrypted tunnel straight to the droplet.

Adding a server = stand up a droplet (Steps 1–16), then register it in Postgres (Steps 17–22).

⚠️ Unique per node

The IP, the WireGuard keypair, and the tunnel subnet. Everything else (agent secret, app key, agent code) is identical across nodes.

Control-plane URL: https://nyx-edge.onrender.com — deliberately neutral (no "vpn") to dodge SNI-based DPI. Not vpn-master-be.onrender.com (doesn't resolve).

HALF A Stand up the droplet · Steps 1–16
1
💻 MacA1Create the droplet

DigitalOcean dashboard → Create Droplet: Ubuntu 24.04 LTS, smallest Basic size ($4–6/mo), region = the city you're adding, Authentication = your digitalocean_vpn_master SSH key. Then copy the public IP — that's <NODE_IP>.

Or via CLI:

brew install doctl && doctl auth init            # paste a DO API token
doctl compute ssh-key list                       # note your key's fingerprint
doctl compute droplet create <SERVER_ID> \
  --region fra1 --image ubuntu-24-04-x64 --size s-1vcpu-1gb \
  --ssh-keys <FINGERPRINT> --wait
2
💻 MacA1Confirm you can SSH in

Accept the host key the first time. Every later ssh/scp uses this same -i key.

ssh -i ~/.ssh/digitalocean_vpn_master root@<NODE_IP>

Expect: a root shell on the droplet. Stay in this session for Steps 3–7, 9, 11–16.

3
🖥️ DropletA2Install packages + enable IP forwarding

ip_forward=1 is what lets the box route tunnel traffic to the internet; it persists across reboot.

apt-get update && apt-get install -y wireguard nftables nodejs npm
echo 'net.ipv4.ip_forward=1' > /etc/sysctl.d/99-wg.conf && sysctl --system
4
🖥️ DropletA3Generate the WireGuard keypair
cd /etc/wireguard
umask 077
wg genkey | tee server.key | wg pubkey > server.pub
cat server.pub

👉 Save the server.pub output — it's the node's public key and goes in the migration (Step 17). The private key server.key never leaves the droplet.

5
🖥️ DropletA3Find your network interface

Look at the word after dev — almost always eth0. If it differs, substitute it in Step 6.

ip route | grep default
6
🖥️ DropletA3Write wg0.conf

Replace <SUBNET_GW> with a real value before pasting — e.g. 10.13.0.1/16 (.1 of your subnet, keep the /16). Leaving the placeholder in makes wg-quick fail to start.

cat > /etc/wireguard/wg0.conf <<EOF
[Interface]
Address = <SUBNET_GW>
PostUp = iptables -I FORWARD 1 -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT; iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE
ListenPort = 51820
PrivateKey = $(cat /etc/wireguard/server.key)
EOF

The two iptables rules matter: -I FORWARD 1 inserts the accept rule at the top so it beats ufw's default-DROP (see T2); MASQUERADE NATs tunnel traffic out.

7
🖥️ DropletA3Bring up wg0 + verify
systemctl enable --now wg-quick@wg0
wg show
iptables -L FORWARD -n -v --line-numbers | head -3
iptables -t nat -L POSTROUTING -n -v | grep -i masq

Expect: wg show → interface wg0, port 51820, your pubkey · FORWARD rule #1 = ACCEPT in wg0 · a MASQUERADE line on eth0.

8
💻 MacA4Deploy the node-agent code

Run from the repo root on your Mac (the agent lives in this repo). This pushes it to the droplet and installs its one dependency.

ssh -i ~/.ssh/digitalocean_vpn_master root@<NODE_IP> 'mkdir -p /opt/vpn-agent'
scp -i ~/.ssh/digitalocean_vpn_master node-agent/index.js root@<NODE_IP>:/opt/vpn-agent/index.js
ssh -i ~/.ssh/digitalocean_vpn_master root@<NODE_IP> 'cd /opt/vpn-agent && npm i express'

Expect: index.js copied (100%) and added NN packages. Later agent changes = re-run the scp + ssh … 'systemctl restart vpn-agent'.

9
🖥️ DropletA5Generate the agent's TLS cert

Self-signed, 10-year, EC key, SAN pinned to the node IP (no domain needed). <CN> = vpn-agent-<SERVER_ID>. Paths are absolute, so any working directory is fine.

openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 -nodes \
  -keyout /opt/vpn-agent/agent.key -out /opt/vpn-agent/agent.crt -days 3650 \
  -subj "/CN=<CN>" -addext "subjectAltName=IP:<NODE_IP>,IP:127.0.0.1"
chmod 600 /opt/vpn-agent/agent.key

Only agent.crt (public) leaves the box. agent.key (private) stays on the droplet, 0600, never copied.

10
💻 MacA5Pull the public cert into the repo

Run from the repo root. You'll commit this file in Step 18.

scp -i ~/.ssh/digitalocean_vpn_master root@<NODE_IP>:/opt/vpn-agent/agent.crt certs/<SERVER_ID>-agent.crt
openssl x509 -in certs/<SERVER_ID>-agent.crt -noout -subject -ext subjectAltName

Expect: subject=CN=vpn-agent-<SERVER_ID> and a SAN of IP Address:<NODE_IP>, IP Address:127.0.0.1.

11
🖥️ DropletA6Write the systemd unit

Write it with a placeholder secret first (Step 12 fills it in), so the real secret never hits your shell history.

cat > /etc/systemd/system/vpn-agent.service <<'EOF'
[Unit]
Description=VPN Master Node Agent
After=network.target wg-quick@wg0.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/vpn-agent
Environment=AGENT_SECRET=PASTE_SECRET_HERE
Environment=TLS_CERT_FILE=/opt/vpn-agent/agent.crt
Environment=TLS_KEY_FILE=/opt/vpn-agent/agent.key
Environment=AGENT_TLS_PORT=8443
ExecStart=/usr/bin/node index.js
Restart=always

[Install]
WantedBy=multi-user.target
EOF
12
🖥️ Droplet☁️ RenderA6Insert the real NODE_AGENT_SECRET

Copy the value from Render → VPN-Master-BE → Environment → NODE_AGENT_SECRET, then edit it into the unit:

nano /etc/systemd/system/vpn-agent.service

In nano: Ctrl+\ (Replace) → find PASTE_SECRET_HERE → paste the secret → A (all) → Ctrl+O, Enter → Ctrl+X.

⚠️ Do NOT quote the secret

systemd treats quotes literally, so AGENT_SECRET="abc" makes the secret "abc" and auth fails (see T5).

13
🖥️ DropletA6Start the service + verify it stays up
systemctl daemon-reload && systemctl enable --now vpn-agent
sleep 3; systemctl status vpn-agent --no-pager -l
journalctl -u vpn-agent -n 20 --no-pager

Expect: active (running) with uptime growing (not resetting), Main PID = node index.js, memory ~30 MB, and a log line VPN Agent HTTPS on port 8443. Crash-looping ms-uptime + tiny memory = bad secret (see T5).

14
☁️ RenderA7Get Render's outbound IP ranges

Render → VPN-Master-BE → Connect → Outbound. Known-good: 74.220.48.0/24 and 74.220.56.0/24. If Render shows different ranges, use those — wrong ranges silently drop the control plane (see T3).

15
🖥️ DropletA7Apply the firewall

Locks :8443 to Render only; keeps SSH + WireGuard open. Port 22 is allowed first so enabling ufw can't lock you out. Swap in your Step 14 ranges if they differ.

ufw allow 22/tcp
ufw allow 51820/udp
ufw allow from 74.220.48.0/24 to any port 8443 proto tcp
ufw allow from 74.220.56.0/24 to any port 8443 proto tcp
echo y | ufw enable
ufw status verbose

Expect: 22/tcp + 51820/udp from Anywhere; 8443/tcp only from the two Render ranges. Default: deny (routed) is fine — the wg0 rule from Step 6 handles forwarding.

16
🖥️ DropletA8Smoke-test the agent locally

Confirms TLS + secret + quota table work before Render ever calls it. Reads the secret from systemd so you don't paste it again.

SECRET=$(systemctl show vpn-agent -p Environment --value | tr ' ' '\n' | sed -n 's/^AGENT_SECRET=//p')
curl --cacert /opt/vpn-agent/agent.crt https://127.0.0.1:8443/metrics -H "X-Agent-Secret: $SECRET"
nft list table inet wgquota

Expect: curl → {"peers":[]} (empty is correct) · the wgquota table exists with an empty forward chain, policy accept. ✅ Half A done.

HALF B Register the node in the control plane · Steps 17–22

No cert step here. services/provisioner/nodeHttp.js auto-trusts every certs/*.crt, so the file you pulled in Step 10 makes the node trusted the moment it's deployed. Nothing to configure.

17
🗄️ SQLB2Write the migration

Create the next-numbered file in db/migrations/ (applied once, in filename order, on every boot).

If <SERVER_ID> already exists as a mock seed (de-fra-01, gb-lon-01, sg-sin-01) → it's an UPDATE:

-- db/migrations/00N_activate_<server_id>.sql   (bump N!)
UPDATE servers
SET endpoint      = '<NODE_IP>:51820',
    public_key    = '<server.pub from Step 4>',
    tunnel_subnet = '<SUBNET>',
    provisioner   = 'agent',
    agent_url     = 'https://<NODE_IP>:8443',
    enabled       = true,
    updated_at    = now()
WHERE id = '<SERVER_ID>';

If it's a brand-new region → INSERT the full row:

INSERT INTO servers
  (id, name, country, country_code, city, endpoint, public_key,
   tunnel_subnet, load, is_premium, provisioner, agent_url, enabled)
VALUES
  ('<SERVER_ID>', '<City Name>', '<Country>', '<CC>', '<City>',
   '<NODE_IP>:51820', '<public_key>', '<SUBNET>', 0.30, false,
   'agent', 'https://<NODE_IP>:8443', true)
ON CONFLICT (id) DO UPDATE SET
  endpoint = EXCLUDED.endpoint, public_key = EXCLUDED.public_key,
  tunnel_subnet = EXCLUDED.tunnel_subnet, provisioner = EXCLUDED.provisioner,
  agent_url = EXCLUDED.agent_url, enabled = EXCLUDED.enabled, updated_at = now();

country_code is ISO 3166-1 alpha-2 (DE, GB, SG) — it drives the flag emoji in the app.

18
💻 MacB3Commit the cert + migration + registry

Include the §2 registry update (mark your subnet taken) in the same commit.

git add certs/<SERVER_ID>-agent.crt db/migrations/00N_activate_<server_id>.sql docs/RUNBOOK-add-server.html
git commit -m "servers: activate <SERVER_ID> (real WireGuard node, <City>)"
19
💻 MacB3Push → Render deploys + runs the migration
git push

Expect (Render deploy logs): [db] ✓ 00N_activate_<server_id>.sql then ==> Your service is live 🎉.

20
💻 MacB4Verify: catalog shows the real node

Replace PASTE_REAL_KEY with API_KEYS from Render.

curl -sS https://nyx-edge.onrender.com/v1/servers -H 'X-API-Key: PASTE_REAL_KEY' \
  | jq '.[] | select(.id=="<SERVER_ID>")'

Expect: the real endpoint <NODE_IP>:51820 and publicKey.

21
💻 MacB4Verify: a real session (the true proof)

This exercises the agent over TLS end-to-end.

curl -sS -w '\nHTTP %{http_code}\n' -X POST https://nyx-edge.onrender.com/v1/sessions \
  -H 'X-API-Key: PASTE_REAL_KEY' -H 'Content-Type: application/json' \
  -d '{"serverID":"<SERVER_ID>","publicKey":"'"$(head -c32 /dev/urandom | base64)"'"}'

Expect: HTTP 200 with assignedAddresses in your <SUBNET> range + a quota block.

22
💻 MacB4Verify: the peer landed in the kernel
ssh -i ~/.ssh/digitalocean_vpn_master root@<NODE_IP> \
  'wg show wg0 | sed -n "/peer:/,\$p"; nft list table inet wgquota'

Expect: a peer: line with allowed ips: <allocated IP>/32 and a q_<ip> quota armed at ~1 GB. ✅ Node is production-live. The test peer has no handshake, so the reaper auto-removes it within PEER_TTL_MINUTES (30) — nothing to clean up.

↩ Rollback #

Pull a node out of rotation instantly (no redeploy) — run against the Render Postgres (psql "$DATABASE_URL" or the dashboard DB shell):

-- take it offline (stays in catalog but /sessions refuses it)
UPDATE servers SET enabled = false WHERE id = '<SERVER_ID>';

-- OR revert to a harmless mock (won't call the agent)
UPDATE servers SET provisioner = 'mock', agent_url = NULL WHERE id = '<SERVER_ID>';

Then destroy the droplet in DigitalOcean if you're decommissioning it.

🔧 Troubleshooting — gotchas we actually hit #

T1 · HTTP 000 from a verification curl

curl got no response at all — almost always the wrong URL: it's https://nyx-edge.onrender.com, not vpn-master-be.onrender.com (doesn't resolve). Check the service is "Live" and run with -sS to see the real error.

T2 · Handshake works but no internet through the tunnel

The iptables -I FORWARD 1 -i wg0 -j ACCEPT rule (Step 6) is missing or below ufw's forward chain. It must be rule #1. Verify: iptables -L FORWARD -n -v --line-numbers | head -3. Also confirm sysctl net.ipv4.ip_forward → 1 and the MASQUERADE rule exists.

T3 · Control plane can't reach the agent (/sessions → "Could not reach the VPN node")

The ufw rule for :8443 (Step 15) doesn't match Render's current outbound ranges — a plan/region change shifts them and the firewall drops the control plane silently. Diagnose on the droplet while a /sessions fires:

tcpdump -tni eth0 'tcp and dst port 8443 and tcp[tcpflags] & tcp-syn != 0' \
  | awk '{print $3}' | sed 's/\.[0-9]*$//' | sort -u

Compare against Render → Connect → Outbound, then re-add the ufw allow from <range> to any port 8443 proto tcp rules.

T4 · Logs show poll <SERVER_ID> failed: self-signed certificate

Usually transient during Render's zero-downtime deploy (the old instance polls the new node before it trusted the cert). If it keeps recurring after the deploy finishes, confirm the cert is committed and that the fingerprints match:

# Mac     openssl x509 -in certs/<SERVER_ID>-agent.crt -noout -fingerprint -sha256
# Droplet openssl x509 -in /opt/vpn-agent/agent.crt -noout -fingerprint -sha256

The two SHA-256 fingerprints must be identical. If not, re-pull (Step 10) and re-commit.

T5 · Agent won't start / auth fails

journalctl -u vpn-agent -n 30 --no-pager on the droplet. Most common: AGENT_SECRET is still PASTE_SECRET_HERE, is quoted, or doesn't match Render's NODE_AGENT_SECRET. Fix the unit (Step 12), then systemctl daemon-reload && systemctl restart vpn-agent.
